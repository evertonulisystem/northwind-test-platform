CEN-R01: Campos Obrigatórios Ausentes

400 Bad Request
Gherkin (BDD) 
Funcionalidade: Validação da API de Registro de Usuário

  Cenário: Registro de usuário omitindo algum campo obrigatório
    Dado que o cliente envia uma requisição POST de cadastro
    Quando omitir um ou mais dos seguintes campos obrigatórios:
      | campo | mensagem de erro esperada |
      | "full_name" | "Nome completo é obrigatório" |
      | "email" | "Email é obrigatório" |
      | "password" | "Senha é obrigatória" |
      | "confirmPassword" | "Confirmação de senha é obrigatória" |
    Então a API deve responder com o código de status HTTP 400 Bad Request
    E o corpo da resposta deve conter a lista correspondente de mensagens de erros de obrigatoriedade
Trecho do Código na API:
const missingFields = [];
if (!full_name) missingFields.push('Nome completo é obrigatório');
if (!email) missingFields.push('Email é obrigatório');
if (!password) missingFields.push('Senha é obrigatória');
if (!confirmPassword) missingFields.push('Confirmação de senha é obrigatória');

if (missingFields.length > 0) {
  return Response.json({ data: null, mensagens: missingFields }, { status: 400 });
}

CEN-R10: Requisitos de Complexidade da Senha

400 Bad Request
Gherkin (BDD) 
Funcionalidade: Validação da API de Registro de Usuário

  Esquema do Cenário: Registro de usuário com senha que não cumpre os requisitos mínimos
    Dado que o cliente envia uma requisição POST de cadastro
    Quando a senha fornecida violar o <requisito>
    Então a API deve responder com o código de status HTTP 400 Bad Request
    E o corpo da resposta deve conter a mensagem de base "Senha inválida" junto com o <suberro>

    Exemplos:
      | requisito | exemplo_senha | suberro |
      | Mínimo de 8 caracteres | "Abc1!" | "Mínimo de 8 caracteres" |
      | Pelo menos 1 letra maiúscula | "senha@123" | "Pelo menos 1 letra maiúscula" |
      | Pelo menos 1 letra minúscula | "SENHA@123" | "Pelo menos 1 letra minúscula" |
      | Pelo menos 1 número | "Senha@Especial" | "Pelo menos 1 número" |
      | Pelo menos 1 caractere especial | "Senha12345" | "Pelo menos 1 caractere especial" |
Trecho do Código na API:
function validatePassword(password) {
  const errors = [];
  if (password.length < 8) errors.push('Mínimo de 8 caracteres');
  if (!/[A-Z]/.test(password)) errors.push('Pelo menos 1 letra maiúscula');
  if (!/[a-z]/.test(password)) errors.push('Pelo menos 1 letra minúscula');
  if (!/[0-9]/.test(password)) errors.push('Pelo menos 1 número');
  if (!/[!@#$%^&*(),.?":{}|<>_+\-=\[\]';\\/`~]/.test(password)) errors.push('Pelo menos 1 caractere especial');
  return errors;
}

CEN-R14: Email Já Cadastrado

409 Conflict
Gherkin (BDD) 
Funcionalidade: Validação da API de Registro de Usuário

  Cenário: Tentativa de registro usando um email que já está cadastrado por outro usuário
    Dado que existe um usuário registrado no banco de dados com o email "admin@qatest.com"
    Quando um novo cliente tenta se cadastrar fornecendo este mesmo e-mail "admin@qatest.com"
    Então a API deve responder com o código de status HTTP 409 Conflict
    E o corpo da resposta deve conter na lista de mensagens: "Email já cadastrado. Tente fazer login ou use outro email"
Trecho do Código na API:
const { data: existingUser } = await supabase
  .from('users')
  .select('id')
  .eq('email', email)
  .single();

if (existingUser) {
  return Response.json(
    { data: null, mensagens: ['Email já cadastrado. Tente fazer login ou use outro email'] },
    { status: 409 }
  );
}

CEN-R15: Falha na Inserção do Usuário no Banco

500 Internal Error
Gherkin (BDD) 
Funcionalidade: Validação da API de Registro de Usuário

  Cenário: Erro operacional ou de permissão do banco ao salvar o registro do usuário
    Dado que a requisição atende a todas as validações de formato e campos
    Quando o banco de dados do Supabase retornar um erro na query de insert do novo usuário
    Então a API deve responder com o código de status HTTP 500 Internal Server Error
    E o corpo da resposta deve conter na lista de mensagens: "Erro ao criar usuário. Tente novamente mais tarde"
Trecho do Código na API:
const { data: newUser, error: insertError } = await supabase
  .from('users')
  .insert({ ... })
  .select()
  .single();

if (insertError) {
  console.error('Erro ao inserir usuário:', insertError);
  return Response.json(
    { data: null, mensagens: ['Erro ao criar usuário. Tente novamente mais tarde'] },
    { status: 500 }
  );
}

CEN-R16: Registro Efetuado com Sucesso

201 Created
Gherkin (BDD) 
Funcionalidade: Validação da API de Registro de Usuário

  Cenário: Cadastro de usuário realizado com sucesso em fluxo íntegro
    Dado que a requisição contém todos os campos obrigatórios preenchidos
    E o nome completo, email e senha atendem a todas as validações estruturais
    E o email informado não está cadastrado por nenhum outro usuário
    Quando a requisição for enviada com sucesso
    Então o servidor deve criptografar a senha do usuário com hash bcrypt
    E deve cadastrar o usuário no banco com o cargo "customer" e status ativo (is_active = true)
    E deve responder com o código de status HTTP 201 Created
    E o corpo da resposta deve conter o token JWT gerado e os dados públicos do usuário registrado
    E a mensagem na propriedade "mensagens" deve ser: "Usuário cadastrado com sucesso"
Trecho do Código na API:
// Retornar sucesso
return Response.json({
  data: {
    token,
    user: { id: newUser.id, full_name: newUser.full_name, email: newUser.email, role: newUser.role }
  },
  mensagens: 'Usuário cadastrado com sucesso'
}, { status: 201 });

CEN-R17: Erro Crítico / Exceção no Servidor

Gherkin (BDD)

  Cenário: Ocorrência de exceção de servidor genérica na execução da API
    Dado que ocorre um erro inesperado no backend (ex: erro de runtime, falta de variáveis de ambiente)

    E o corpo da resposta deve conter na lista de mensagens: "Erro interno do servidor. Tente novamente mais tarde"
Trecho do Código na API:
} catch (error) {
  console.error('Erro no registro:', error);
  return Response.json(
    { data: null, mensagens: ['Erro interno do servidor. Tente novamente mais tarde'] },
    { status: 500 }
  );
}
