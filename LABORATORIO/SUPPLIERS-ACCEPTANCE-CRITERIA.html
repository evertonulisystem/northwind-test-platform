Teste de API com Playwright | Prof. Everton Ulisses

User Story

Como: Desenvolvedor de Testes Automatizados

Eu quero: Validar todos os endpoints da API de Suppliers

Para que: Garantir que as regras de negócio, validações e respostas HTTP estejam funcionando corretamente antes de colocar em produção

Critérios de Aceite: Todos os endpoints devem validar dados, retornar status codes corretos e manter consistência nas respostas JSON.

Acceptance Criteria - Suppliers API

GET Listar Fornecedores
GET /api/v1/suppliers

Query Parameters (Opcionais)

page: Número da página (padrão: 1, mínimo: 1)
limit: Itens por página (padrão: 10, máximo: 100)
search: Busca textual no nome da empresa (case insensitive)
sort: Campo de ordenação: company_name, contact_name, created_at
order: Direção: asc, desc (padrão: asc)

Status Codes Esperados

200 400 401 500
  • ✅ Listagem com paginação funcional: Retorna fornecedores paginados com metadados
  • ✅ Filtros aplicados corretamente: Filtra por busca textual e ordenação
  • ✅ Token obrigatório: Requer JWT válido no header Authorization
  • ✅ Validação de parâmetros: Valida page/limit como números positivos
  • ✅ Estrutura JSON consistente: Retorna { data, mensagens } em todas as respostas
POST Criar Fornecedor
POST /api/v1/suppliers

Body (JSON) - Campos Obrigatórios

company_name: Nome da empresa (2-100 caracteres, único)
contact_name: Nome do contato (2-100 caracteres)
email: Email do fornecedor (formato email válido, único)
phone: Telefone (10-15 caracteres, formato internacional)

Status Codes Esperados

201 400 401 409 500
  • ✅ Criação com sucesso: Fornecedor criado com ID único
  • ✅ Validação de campos obrigatórios: Retorna erro se campos ausentes ou inválidos
  • ✅ Validação de unicidade: Impede email ou nome de empresa duplicado
  • ✅ Validação de email: Verifica formato de email válido
  • ✅ Validação de telefone: Verifica formato de telefone válido
GET Buscar Fornecedor por ID
GET /api/v1/suppliers/{id}

Path Parameters

id: ID do fornecedor (inteiro positivo, deve existir)

Status Codes Esperados

200 400 401 404 500
  • ✅ Busca por ID funcional: Retorna fornecedor específico com todos os dados
  • ✅ Validação de ID: Valida ID como número positivo
  • ✅ Fornecedor não encontrado: Retorna 404 se fornecedor não existe
  • ✅ Dados completos: Retorna todos os campos incluindo data de criação
GET Listar Produtos do Fornecedor
GET /api/v1/suppliers/{id}/products

Path Parameters

id: ID do fornecedor (inteiro positivo, deve existir)

Status Codes Esperados

200 400 401 404 500
  • ✅ Listagem de produtos funcional: Retorna produtos do fornecedor específico
  • ✅ Fornecedor deve existir: Retorna 404 se fornecedor não existe
  • ✅ Lista vazia permitida: Retorna lista vazia se não houver produtos
  • ✅ Dados relacionais: Inclui nome da categoria dos produtos
PUT Atualizar Fornecedor (Completo)
PUT /api/v1/suppliers/{id}

Body (JSON) - Campos Obrigatórios

company_name: Nome da empresa (2-100 caracteres, único)
contact_name: Nome do contato (2-100 caracteres)
email: Email do fornecedor (formato email válido, único)
phone: Telefone (10-15 caracteres, formato internacional)

Status Codes Esperados

200 400 401 404 409 500
  • ✅ Atualização completa: Atualiza todos os campos do fornecedor
  • ✅ Validação de unicidade: Verifica email e nome duplicados (exceto si mesmo)
  • ✅ Fornecedor não encontrado: Retorna 404 se fornecedor não existe
  • ✅ Validação de formatos: Verifica email e telefone válidos
PATCH Atualizar Fornecedor (Parcial)
PATCH /api/v1/suppliers/{id}

Body (JSON) - Pelo menos um campo obrigatório

company_name: Nome da empresa (2-100 caracteres, opcional)
contact_name: Nome do contato (2-100 caracteres, opcional)
email: Email do fornecedor (formato email válido, opcional)
phone: Telefone (10-15 caracteres, opcional)

Status Codes Esperados

200 400 401 404 409 500
  • ✅ Atualização parcial funcional: Atualiza apenas os campos enviados
  • ✅ Pelo menos um campo obrigatório: Retorna erro se nenhum campo for enviado
  • ✅ Validação de campos individuais: Valida apenas os campos enviados
  • ✅ Validação de unicidade parcial: Verifica duplicados apenas para campos alterados
DELETE Remover Fornecedor
DELETE /api/v1/suppliers/{id}

Path Parameters

id: ID do fornecedor a ser removido (inteiro positivo)

Status Codes Esperados

200 400 401 404 500
  • ✅ Remoção funcional: Remove fornecedor permanentemente
  • ✅ Validação de ID: Valida ID como número positivo
  • ✅ Fornecedor não encontrado: Retorna 404 se fornecedor não existe
  • ✅ Confirmação de remoção: Retorna mensagem de sucesso
POST Upload de Documento
POST /api/v1/suppliers/{id}/document

Body (multipart/form-data)

file: Arquivo PDF (máximo 2MB)

Status Codes Esperados

200 400 401 404 500
  • ✅ Upload de PDF funcional: Aceita apenas arquivos PDF
  • ✅ Validação de tamanho: Rejeita arquivos maiores que 2MB
  • ✅ Fornecedor deve existir: Retorna 404 se fornecedor não existe
  • ✅ URL de retorno: Retorna URL para acesso ao documento
