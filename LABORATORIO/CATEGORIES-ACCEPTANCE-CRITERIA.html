User Story

Como: Desenvolvedor de Testes Automatizados

Eu quero: Validar todos os endpoints da API de Categories

Para que: Garantir que as regras de negócio, validações e respostas HTTP estejam funcionando corretamente antes de colocar em produção

Critérios de Aceite: Todos os endpoints devem validar dados, retornar status codes corretos e manter consistência nas respostas JSON.

Acceptance Criteria - Categories API

GET Listar Categorias
GET /api/v1/categories

Query Parameters (Opcionais)

page: Número da página (padrão: 1, mínimo: 1)
limit: Itens por página (padrão: 10, máximo: 100)
search: Busca textual no nome (case insensitive)
sort: Campo de ordenação: name, created_at
order: Direção: asc, desc (padrão: asc)

Status Codes Esperados

200 400 401 500
  • ✅ Listagem com paginação funcional: Retorna categorias paginadas com metadados
  • ✅ Filtros aplicados corretamente: Filtra por busca textual e ordenação
  • ✅ Token obrigatório: Requer JWT válido no header Authorization
  • ✅ Validação de parâmetros: Valida page/limit como números positivos
  • ✅ Estrutura JSON consistente: Retorna { data, mensagens } em todas as respostas
POST Criar Categoria
POST /api/v1/categories

Body (JSON) - Campos Obrigatórios

name: Nome da categoria (1-25 caracteres, único)
description: Descrição (6-40 caracteres)

Status Codes Esperados

201 400 401 409 500
  • ✅ Criação com sucesso: Categoria criada com slug gerado automaticamente
  • ✅ Validação de campos obrigatórios: Retorna erro se campos ausentes ou inválidos
  • ✅ Validação de unicidade: Impede nome de categoria duplicado
  • ✅ Validação de tamanho: Verifica limites de caracteres
  • ✅ Slug automático: Gera slug a partir do nome
GET Buscar Categoria por ID
GET /api/v1/categories/{id}

Path Parameters

id: ID da categoria (inteiro positivo, deve existir)

Status Codes Esperados

200 400 401 404 500
  • ✅ Busca por ID funcional: Retorna categoria específica com todos os dados
  • ✅ Validação de ID: Valida ID como número positivo
  • ✅ Categoria não encontrada: Retorna 404 se categoria não existe
  • ✅ Dados completos: Retorna todos os campos incluindo slug
GET Listar Produtos da Categoria
GET /api/v1/categories/{id}/products

Path Parameters

id: ID da categoria (inteiro positivo, deve existir)

Status Codes Esperados

200 400 401 404 500
  • ✅ Listagem de produtos funcional: Retorna produtos da categoria específica
  • ✅ Categoria deve existir: Retorna 404 se categoria não existe
  • ✅ Lista vazia permitida: Retorna lista vazia se não houver produtos
  • ✅ Dados relacionais: Inclui nome do fornecedor dos produtos
PUT Atualizar Categoria (Completo)
PUT /api/v1/categories/{id}

Body (JSON) - Campos Obrigatórios

name: Nome da categoria (1-25 caracteres, único)
description: Descrição (6-40 caracteres)

Status Codes Esperados

200 400 401 404 409 500
  • ✅ Atualização completa: Atualiza todos os campos da categoria
  • ✅ Slug regerado se nome mudar: Gera novo slug se nome for alterado
  • ✅ Validação de unicidade: Verifica nome duplicado (exceto si mesmo)
  • ✅ Categoria não encontrada: Retorna 404 se categoria não existe
PATCH Atualizar Categoria (Parcial)
PATCH /api/v1/categories/{id}

Body (JSON) - Pelo menos um campo obrigatório

name: Nome da categoria (1-25 caracteres, opcional)
description: Descrição (6-40 caracteres, opcional)

Status Codes Esperados

200 400 401 404 409 500
  • ✅ Atualização parcial funcional: Atualiza apenas os campos enviados
  • ✅ Pelo menos um campo obrigatório: Retorna erro se nenhum campo for enviado
  • ✅ Slug regerado apenas se necessário: Gera slug apenas se nome for alterado
  • ✅ Validação de campos individuais: Valida apenas os campos enviados
DELETE Remover Categoria
DELETE /api/v1/categories/{id}

Path Parameters

id: ID da categoria a ser removida (inteiro positivo)

Status Codes Esperados

200 400 401 404 500
  • ✅ Remoção funcional: Remove categoria permanentemente
  • ✅ Validação de ID: Valida ID como número positivo
  • ✅ Categoria não encontrada: Retorna 404 se categoria não existe
  • ✅ Confirmação de remoção: Retorna mensagem de sucesso
POST Upload de Imagem
POST /api/v1/categories/{id}/image

Body (multipart/form-data)

file: Arquivo PNG (máximo 2MB)

Status Codes Esperados

200 400 401 404 500
  • ✅ Upload de PNG funcional: Aceita apenas arquivos PNG
  • ✅ Validação de tamanho: Rejeita arquivos maiores que 2MB
  • ✅ Categoria deve existir: Retorna 404 se categoria não existe
  • ✅ URL de retorno: Retorna URL para acesso à imagem
POST Upload de PDF
POST /api/v1/categories/{id}/pdf

Body (multipart/form-data)

file: Arquivo PDF (máximo 2MB)

Status Codes Esperados

200 400 401 404 500
  • ✅ Upload de PDF funcional: Aceita apenas arquivos PDF
  • ✅ Validação de tamanho: Rejeita arquivos maiores que 2MB
  • ✅ Categoria deve existir: Retorna 404 se categoria não existe
  • ✅ URL de retorno: Retorna URL para acesso ao PDF
