Teste de API com Playwright | Prof. Everton Ulisses

User Story

Como: Desenvolvedor de Testes Automatizados

Eu quero: Validar todos os endpoints da API de Products

Para que: Garantir que as regras de negócio, validações e respostas HTTP estejam funcionando corretamente antes de colocar em produção

Critérios de Aceite: Todos os endpoints devem validar dados, retornar status codes corretos e manter consistência nas respostas JSON.

Acceptance Criteria - Products API

GET Listar Produtos
GET /api/v1/products

Query Parameters (Opcionais)

page: Número da página (padrão: 1, mínimo: 1)
limit: Itens por página (padrão: 10, máximo: 100)
search: Busca textual no nome do produto (case insensitive)
category_id: Filtrar por ID da categoria (deve existir)
supplier_id: Filtrar por ID do fornecedor (deve existir)
sort: Campo de ordenação: name, price, stock_quantity, created_at
order: Direção da ordenação: asc, desc (padrão: asc)

Status Codes Esperados

200 400 401 500
  • ✅ Listagem com paginação funcional: Retorna produtos paginados com metadados (page, limit, total, totalPages)
  • ✅ Filtros funcionando corretamente: Aplica filtros de categoria, fornecedor e busca textual
  • ✅ Ordenação por múltiplos campos: Permite ordenar por nome, preço, estoque e data
  • ✅ Token obrigatório: Requer JWT válido no header Authorization
  • ✅ Validação de parâmetros: Valida page/limit como números positivos
  • ✅ Estrutura JSON consistente: Retorna { data, mensagens } em todas as respostas
POST Criar Produto
POST /api/v1/products

Body (JSON) - Campos Obrigatórios

name: Nome completo do produto (obrigatório, entre 3 e 100 caracteres, deve ser descritivo e único)
price: Preço de venda do produto (obrigatório, deve ser maior que 0, use 2 casas decimais)
stock_quantity: Quantidade em estoque (obrigatório, número inteiro, não pode ser negativo, atualiza automaticamente)
sku: SKU do produto (obrigatório, código único em maiúsculas, 6-20 caracteres alfanuméricos, sem espaços)
category_id: ID da categoria (obrigatório, deve existir na tabela categories, use 1 para 'Eletrônicos')
supplier_id: ID do fornecedor (obrigatório, deve existir na tabela suppliers, use 1 para fornecedor padrão)

Status Codes Esperados

201 400 401 409 500
  • ✅ Criação com sucesso: Produto criado com slug gerado automaticamente
  • ✅ Validação de campos obrigatórios: Retorna erro se campos obrigatórios ausentes
  • ✅ Validação de unicidade: Impede SKU ou nome duplicados
  • ✅ Validação de tipos: Verifica tipos dos dados (number, string, integer)
  • ✅ Slug automático: Gera slug a partir do nome automaticamente
GET Buscar Produto por ID
GET /api/v1/products/{id}

Path Parameters

id: ID do produto (inteiro positivo, deve existir)

Status Codes Esperados

200 400 401 404 500
  • ✅ Busca por ID funcional: Retorna produto específico com todos os dados
  • ✅ Validação de ID: Valida ID como número positivo
  • ✅ Produto não encontrado: Retorna 404 se produto não existe
  • ✅ Dados relacionais: Inclui nome da categoria e fornecedor
PUT Atualizar Produto (Completo)
PUT /api/v1/products/{id}

Body (JSON) - Todos os campos obrigatórios

name: Nome completo do produto (obrigatório, entre 3 e 100 caracteres)
price: Preço de venda do produto (obrigatório, número > 0, 2 casas decimais)
stock_quantity: Quantidade em estoque (obrigatório, inteiro ≥ 0)
sku: SKU do produto (obrigatório, 6-20 caracteres, maiúsculas)
category_id: ID da categoria existente (obrigatório)
supplier_id: ID do fornecedor existente (obrigatório)

Status Codes Esperados

200 400 401 404 409 500
  • ✅ Atualização completa: Atualiza todos os campos do produto
  • ✅ Slug regerado se nome mudar: Gera novo slug se nome for alterado
  • ✅ Validação de unicidade: Verifica SKU e nome duplicados
  • ✅ Produto não encontrado: Retorna 404 se produto não existe
PATCH Atualizar Produto (Parcial)
PATCH /api/v1/products/{id}

Body (JSON) - Pelo menos um campo obrigatório

name: Nome do produto (opcional, 3-100 caracteres, gera novo slug)
price: Preço do produto (opcional, número > 0, 2 casas decimais)
stock_quantity: Quantidade em estoque (opcional, inteiro ≥ 0)
sku: SKU do produto (opcional, 6-20 caracteres, maiúsculas)
category_id: ID da categoria existente (opcional)
supplier_id: ID do fornecedor existente (opcional)

Status Codes Esperados

200 400 401 404 409 500
  • ✅ Atualização parcial funcional: Atualiza apenas os campos enviados
  • ✅ Pelo menos um campo obrigatório: Retorna erro se nenhum campo for enviado
  • ✅ Slug regerado apenas se necessário: Gera slug apenas se nome for alterado
  • ✅ Validação de campos individuais: Valida apenas os campos enviados
DELETE Remover Produto
DELETE /api/v1/products/{id}

Path Parameters

id: ID do produto a ser removido (inteiro positivo)

Status Codes Esperados

200 400 401 404 500
  • ✅ Remoção funcional: Remove produto permanentemente
  • ✅ Validação de ID: Valida ID como número positivo
  • ✅ Produto não encontrado: Retorna 404 se produto não existe
  • ✅ Confirmação de remoção: Retorna mensagem de sucesso
POST Upload de Imagem
POST /api/v1/products/{id}/image

Body (multipart/form-data)

file: Arquivo PNG (máximo 2MB)

Status Codes Esperados

200 400 401 404 500
  • ✅ Upload de PNG funcional: Aceita apenas arquivos PNG
  • ✅ Validação de tamanho: Rejeita arquivos maiores que 2MB
  • ✅ Produto deve existir: Retorna 404 se produto não existe
  • ✅ URL de retorno: Retorna URL para acesso à imagem
POST Upload de PDF
POST /api/v1/products/{id}/pdf

Body (multipart/form-data)

file: Arquivo PDF (máximo 2MB)

Status Codes Esperados

200 400 401 404 500
  • ✅ Upload de PDF funcional: Aceita apenas arquivos PDF
  • ✅ Validação de tamanho: Rejeita arquivos maiores que 2MB
  • ✅ Produto deve existir: Retorna 404 se produto não existe
  • ✅ URL de retorno: Retorna URL para acesso ao PDF
